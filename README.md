# Lunara

Telegram-бот расписания МИИГАиК на Go. Реализован **этап 2 из 7**:
каркас процесса, календарь недель, HTTP-клиент МИИГАиК и HTML-парсер.
PostgreSQL-хранилище, Telegram и watcher пока не подключены.

## Локальный запуск

Требуется Go 1.26 или новее. HTML разбирается через goquery; версии зависимостей закреплены в go.mod/go.sum.
Приложение читает переменные окружения; автоматически `.env` не загружает.

```sh
go run ./cmd/bot
```

Процесс запускается с настройками по умолчанию, пишет JSON-логи и ждёт
SIGINT/SIGTERM; сейчас он не получает расписание и не отправляет сообщения.

Настройки перечислены в `.env.example`. По умолчанию группа `1306`, зона `Europe/Moscow`, верхняя опорная
неделя с `2025-09-01`. Это правило найдено в публичном JavaScript
https://study.miigaik.ru/static/schedule/js/schedule-page.js; его следует сверять
при изменении правил на сайте. Тип опоры допускает `upper` и `lower`.
Недели начинаются в понедельник, считаются календарными днями и не сбрасываются
на границе года. Часовые пояса встроены в бинарный файл.

Модель расписания привязана к группе и конкретной календарной неделе. Границы учебных
периодов для этого не нужны; опорная дата только определяет чередование недель
и не ограничивает доступные даты расписания.

## Проверка источника

Разовая загрузка недели (вывод нормализованного расписания в JSON):

```sh
go run ./cmd/schedule -date 2026-09-28
```

Без `-date` выбирается текущая неделя. Группа задаётся через `GROUP_ID`.
Команда имеет общий тайм-аут одну минуту, пишет ошибки в stderr и завершает работу.
`cmd/bot` пока не запускает загрузку автоматически.

Клиент запрашивает полную страницу по `groupId`, `dateStart`, `dateEnd`.
Тайм-аут одной попытки — не более 15 секунд, размер ответа — не более 2 МиБ.
Не более трёх попыток при временных сетевых ошибках, HTTP 429 и 5xx;
между запросами минимум секунда. `Retry-After` учитывается, ожидание прерывается
контекстом. Все запросы одного клиента последовательны, редиректы запрещены.

Парсер проверяет выбранную группу, заголовок, диапазон дат, дни недели и все
карточки. При ошибке он возвращает нулевой результат, а не частичное расписание.
Явный блок «Нет данных…» даёт статус `unpublished`, **не удаление занятий**.
Поле `CheckedAt` устанавливается только после успешной загрузки.
Парсер принимает полные HTML-документы; HTMX-фрагменты не поддерживаются.

Пробелы и NBSP нормализуются, известные типы занятий приводятся к общим значениям,
неизвестные сохраняются в `RawType`. Занятия и списки преподавателей/аудиторий
сортируются; повторяющиеся занятия сохраняются. Хеш SHA-256 считается по
нормализованным данным, включая группу, календарную неделю, статус и версию
нормализации, без времени загрузки. Сравнение изменений появится на этапе 5.
Подгруппа читается из дополнительного абзаца `Подгруппа: …`; этот вариант покрыт
синтетическим тестом, в сохранённых страницах группы 1306 подгрупп нет.

## Проверки

```sh
go test -race ./...
go vet ./...
go build -o /tmp/lunara-bot ./cmd/bot
```

`Dockerfile` и `compose.yaml` подготовлены для будущего развёртывания.
Docker при разработке этого этапа не запускался; контейнерная сборка не проверена.
Для Compose нужен `.env` на основе примера, включая непустой пароль PostgreSQL.
Порт PostgreSQL наружу не опубликован. На текущем этапе приложение ещё не
подключается к БД; миграции и отдельная задача их запуска появятся на этапе 3.
Образы зафиксированы по тегам; перед реальным развёртыванием их следует обновить
до проверенных исправленных версий и закрепить digest.

## Структура и следующие этапы

- `cmd/bot`: запуск, сигналы и ограниченный контекст завершения.
- `internal/config`: чтение и проверка настроек без вывода секретов.
- `internal/schedule`: модели и календарные операции.
- `internal/source/miigaik`: клиент, parser и тестовые HTML-страницы.
- `cmd/schedule`: разовая проверка загрузки без БД и Telegram.

Этап 2 завершён. Следующий этап 3: PostgreSQL и первичная загрузка недель.
Этап 4: Telegram-команды. Этап 5: сравнение и подтверждение изменений.
Этап 6: watcher и доставка уведомлений. Этап 7: экзамены и опциональные рассылки.
Каждый этап выполняется отдельно после согласования продолжения.
